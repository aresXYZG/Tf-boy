# 中长连续剧 · 分镜表覆盖规则

> 本文件只在项目 `contentFormat=series_drama` 时加载。分镜仍必须遵守通用层的 Track、台词、真实资产、动作连续和 XML 契约。

## 一、长剧镜头第一原则

- 镜头首先服务人物选择、关系变化和主线因果，其次才是场面调度和视觉风格。
- 一场戏可以有观察、反应、停顿和空间呼吸，但每个镜头都应承担行动、信息、关系或情绪功能。

## 二、场面调度与人物弧

- 依据剧本和导演规划设计人物站位、视线、距离、遮挡和走位；同一场内变化要有动作依据。
- 关键选择前保留反应和停顿，让观众看见人物如何决定，而不是只用台词宣布结果。
- 关系变化通过靠近、回避、阻挡、让路、递交/收回道具等可见动作表达，不用抽象标签代替。
- 支线镜头只有在推进支线并与主线或人物弧有关时保留。

## 三、伏笔、信息与集间承接

- 伏笔必须落到具体道具、动作、台词细节、视线或空间关系；不得用神秘氛围代替线索。
- 集末可以落在自然的选择、后果、信息缺口或关系变化；不得添加剧本没有的钩子。
- 下一集承接时，优先保持关键道具状态、人物位置/朝向的合理延续和动作因果；跨时空时明确切换依据。

## 四、时长、片段和资产

- 总时长和镜头密度按项目配置执行。
- 每个 Track 总时长 `≤15秒`；长台词/VO 按语义拆镜，但不删改台词。
- 同一角色跨集优先使用同一基础资产；稳定换装/变身使用衍生资产，瞬时状态不新建。
- 只引用 assets 中真实存在的资产；缺失资产不编造 ID。

## 五、分镜填写

- 场景和人物按剧本真实出场填写。
- 画面描述具体写动作、空间、表情、道具和状态变化，不写“推进人物弧”等抽象结论。
- 台词/VO 原文完整写入；音效只写环境音、动作音和拟音，不写音乐/配乐。
- 相邻镜头景别、视角、运动可错开，但不能为了变化破坏视轴和动作连续。

## 六、输出补充建议

在场头或场尾注意事项中可短注：

```text
本集功能：入局/调查/博弈/关系推进/转折/兑现/代价；主线节点：……；人物选择：……；伏笔落点：……；集末自然承接：……。
```

这段是导演提示，不新增通用表格字段，不代替剧本内容。

## 八、适用边界说明

本文件只在项目 `contentFormat=series_drama` 时加载，其他形态不会读取本文件。
