# 知识科普解说 · 导演规划覆盖规则

> 本文件是 `explainer_video` 的制作阶段覆盖层，不替代通用导演规划。通用层负责场次拆分、台词统计、情绪分析、过渡和 XML 契约；本层负责把知识讲解变成可验证、可拍摄、可交给下游分镜表执行的认知与视觉计划。

## 一、形态第一原则与适用边界

- **第一原则：先制造认知缺口，再用证据和因果把缺口填上。** 科普的核心交付是观众理解了什么，不是画面有多热闹。
- 本形态默认是单篇/单集完整闭环；不使用付费卡点、集末钩子、剧情爽点或为了留存硬造反转。
- VO/旁白是主要叙事轴；固定主角、实验对象、历史人物或概念形象只承担观察、示范和视觉承载功能，不用长对白替代知识讲解。
- 通用层中的“逐场”是制作组织单位，不等同于剧情场次；允许按“现实场景、实验/演示场景、微观机制场景、历史重演场景、图解/数据场景”组织场次，但不得凭空补写原文没有的事实或情节。

## 二、先判定知识结构，不得强套短剧五步法

为本期选择一个主结构；若混合，指定一个主结构并注明辅结构。不得默认使用“Hook → 误区/问题 → 机制 → 推演/验证 → 总结”的固定顺序。

| 类型 | 适用内容 | 主认知路径 |
|---|---|---|
| 机制解释型 | 科学、生物、物理、化学、医学常识、技术原理 | 现象 → 误区 → 核心问题 → 机制 → 证据/例子 → 结论 → 边界 |
| 历史/事件型 | 历史、战争、人物、重大事件、商业史 | 事件 → 背景 → 关键选择 → 因果变化 → 后果 → 后世误解/争议 → 今天的认知 |
| 数据/现象型 | 社会、经济、商业、行业、科技趋势 | 反常现象 → 数据证据 → 直觉解释 → 机制解释 → 变量关系 → 限制/反例 → 结论 |
| 流程/方法型 | 某东西如何工作、如何制造、如何完成 | 最终结果 → 步骤1 → 步骤2 → 步骤3 → 关键瓶颈 → 设计原因 → 总结 |
| 谜题/推理型 | 逻辑谜题、认知实验、递归推理 | 规则 → 初始观察 → 第一次推理 → 信息变化 → 递归/连锁 → 结论 |

- 结构只服务理解，不服务凑齐字段。没有误区、反例或脑洞时写“无”，不得编造。
- 每段知识只保留一条主因果链，复杂内容最多三条并行主链；每条链都要能用一句话回答“为什么”。
- Hook 只制造一个待解问题，不在开头塞入未经解释的结论；高潮优先使用证据、实验、历史后果或反例，极端推演按标注制使用（物理规律支持、标注“假设/思想实验”、不包装成事实）。

## 三、导演规划必须建立的知识契约

除通用层要求的分场汇总、逐场注意事项、场间过渡外，必须在 `<scriptPlan>` 内追加下列短节。以下内容供下游分镜表逐字段读取，写短、写准，不写长篇创作说明。

### 知识结构判定
- 主类型：`机制解释型 / 历史事件型 / 数据现象型 / 流程方法型 / 谜题推理型`
- 辅结构（无则写“无”）：
- 选择原因：一句话说明为什么该结构最能解释本期材料
- 认知闭环：用箭头写出本期实际路径

### Claim Chain（主张链）
| 段/主张 | 主张类型 | 观众问题 | 现象或事实 | 原因/机制 | 证据或例子 | 结论 | 成立条件/边界 |
|---|---|---|---|---|---|---|---|
| C1 | 事实/定义/因果/相关/推断/假设/争议 | … | … | … | … | … | … |

规则：
- 每条主张标注主张类型：事实/定义/因果/相关/推断/假设/争议。**相关不得升级为因果，推断不得写成事实，假设不得写成结论**；类型拿不准时按更弱类型处理。
- 每个核心主张必须标记依据类型：`原文事实 / 实验 / 数据 / 历史记录 / 案例 / 未提供`。
- 输入材料未提供的数字、年份、引用、实验结果和因果结论，写“未提供”，不得自行补全。
- 相关性不得写成因果性；存在争议时标注“争议/待核实”，不替材料裁决。
- 类比不是证据。若使用类比，证据栏仍必须填写真实依据或“未提供”。

### 认知递进与段落功能
逐段写出：`观众原本怎么想 → 新信息/证据 → 认知变成什么 → 下一问为何自然出现`。每段只承担一个认知转折，避免连续堆知识点。

### 视觉转译决策
每个核心主张先继承上游的视觉必要性分级（A 必须视觉化 / B 明显有帮助 / C VO已足够），再指定首选视觉方式，必要时给一种备选：

| 主张/知识点 | 视觉必要性 | 首选视觉方式 | 视觉事件（正在发生什么） | 画面证明什么 | 备选 | 是否需要拟人化 |
|---|---|---|---|---|---|---|
| C1 | A/B/C | 真实场景 / 物理过程 / 微观机制 / 实物尺度 / 时间轴 / 数据具象化 / 空间关系 / 流程动作 / 历史重演 / 拟人化 | … | … | … | 是/否 |

- C 级主张不硬造画面，镜头只作通用承接；A 级主张必须有具体可拍的视觉事件。

- 因果机制优先用物理过程或流程动作；微观机制才考虑微观拟人化；历史优先真实场景重演；数据优先尺度、数量、时间变化或空间关系；抽象关系才用生活类比。
- **拟人化不是默认方案。** 使用时必须登记“概念 → 固定形象 → 固定道具 → 核心动作 → 适用范围”，同一概念全片不得换形象。
- 视觉事件必须能被镜头拍到并承担信息功能；禁止只写“展示原理”“体现复杂”“营造高级感”。

### 节奏与体量
- 先按项目配置总时长；若未配置，依据所需 VO 字数和知识完整性估算，不为填满时长加入无关内容。
- 估算语速统一写明采用值；本形态建议 `180~220字/分钟`，但不得覆盖项目配置或下游已有硬约束。
- 标出高密度知识段后的视觉/认知缓冲；缓冲用于恢复注意力，不承担新知识。不要硬性规定“每30秒一个梗”。
- 每个 Track 仍遵守通用层 ≤15 秒物理约束；Track 是生成批次，不是知识段。不得为了塞进 Track 拆断一条因果链。

## 四、角色与资产计划

- 固定主角团（若项目已有）：沿用真实资产名称/ID，只作观察者、提问者、实验参与者或尺度参照。
- 本期知识角色：只登记材料确实需要的实验对象、历史人物、概念形象等；缺失资产不得在本阶段编造 ID，也不得把知识身份覆盖到固定主角基础资产。
- 稳定且跨多个镜头的整体视觉状态才考虑衍生资产；瞬时表情、局部变化、颜色标记由分镜描述承担。
- 追加 `### 角色资产使用计划`：固定主角团 / 本期知识角色 / 复用边界。没有角色时写“无角色，以实物/图解为主”，不要为了科普强行造角色。

## 五、与通用导演规划的执行关系

- 先按通用流程一次性读取 `get_flowData("script")`，然后完成本层知识契约与通用分场分析；此后不再调用读取工具。
- 场次汇总仍使用通用字段，额外在“该场注意事项”中标注：`认知功能 / 证据落点 / 视觉事件 / 音画关系`，每项都写成可拍的短句。
- 场间过渡按需使用；知识段切换优先通过语义、动作、视线、图形/实物关系衔接，不为凑镜头制造花式转场。
- 不改变剧本中的 VO/台词内容；本层只做分析和落地规划，不重写脚本。

## 六、禁止事项

- 结构以判定的知识结构为准，禁止把本期知识强行套成剧情或空壳套路。
- 禁止把类比写成事实、把相关性写成因果性、把猜测写成结论。
- 禁止用拟人化、视觉奇观、金句或视觉梗替代证据和因果链。
- 禁止为制造 Hook、高潮、悬念而捏造数据、年份、人物、实验、引用或反例。
- 禁止在缺少材料依据时补写医学建议、历史断言、行业数据或科学结论。

## 七、适用边界说明

本文件只在项目 `contentFormat=explainer_video` 时加载，其他形态不会读取本文件。
