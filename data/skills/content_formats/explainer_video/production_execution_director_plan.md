# 趣味科普解说 · 导演规划覆盖规则

> 本文件是 `explainer_video` 的制作阶段覆盖层，不替代通用导演规划。科普解说可以有角色资产：固定主角可以在不同知识故事中持续出演，故事专属角色按本期内容新建或引用。

## 形态定位

- 以 VO/旁白为主要叙事轴，但不是“无人物”形态。可以采用“固定主角团 + 本期知识角色”的组合：固定主角承担观众视角，本期角色承担概念、实验或谜题中的角色功能。
- 每个故事/谜题独立闭环：Hook → 误区/问题 → 机制拆解 → 推演/验证 → 总结。故事之间通过固定主角团、统一画风和连续资产保持系列感。
- 不使用超短剧的付费卡点、集末钩子和剧情爽点公式；时长按知识体量和 VO 字数动态推导。

## 角色资产分层

- **固定主角团**：由项目创建/编辑时用户手动选定，非必选。选定后视为本系列的常驻角色，后续每个故事默认优先引用同一资产 ID，不重复建角色、不换脸。
- **本期知识角色**：服务本期谜题或知识点的角色，如红眼睛居民、蓝眼睛居民、实验对象、科学家。只在本期需要时新建；如果资产库已有同名/同身份角色，优先引用已有资产。
- **游客/观察者身份不是新角色**：固定主角在本期故事里可以扮演游客、旁观者、提问者或实验参与者。改变的是剧情身份/场景任务，不是角色资产本身。
- **稳定形态变化才建衍生**：换装、变身、整体形态变化且会跨多个镜头复用时，才走衍生资产；惊讶、红眼、蓝眼、皱眉等局部/瞬时状态由分镜和提示词表达。若“红眼睛/蓝眼睛”是谜题身份的关键且需要稳定呈现，应作为本期知识角色的明确视觉设定或可复用衍生态登记，不能让固定主角资产被误改。

## 导演规划要求

- 规划中单独登记“固定主角团”“本期知识角色”“角色身份/视觉状态”三类信息，明确哪些角色沿用资产、哪些角色只属于本期。
- 每个故事首次出现固定主角时注明其叙事功能（游客/观察者/提问者），后续故事只写角色在新故事中的功能，不重复建立角色小传。
- VO 负责逻辑推导、谜题规则、递归过程和关键结论；固定主角用可见反应、提问、观察和实验动作承接观众认知，不用角色对白抢走科普主线。
- 画面规划采用“现实游客视角 ↔ 谜题内部角色/概念世界 ↔ 机制可视化”三层切换，确保抽象逻辑落成可拍动作。
- 导演注意事项登记跨故事一致性锚点：角色资产 ID/名称、固定道具、服装基准态、游客团站位关系、统一的视觉识别特征。

## 规划输出补充字段

在通用 `<scriptPlan>` 的结构中追加以下短节：

```markdown
### 角色资产使用计划
- 固定主角团：角色名称（资产ID）→ 本期身份/功能
- 本期知识角色：角色名称（资产ID或“待建本期资产”）→ 规则/概念功能
- 复用边界：哪些角色跨故事复用；哪些角色仅本期有效；哪些视觉状态走衍生资产
```

## 禁止事项

- 禁止因为“科普”二字默认删除角色资产。
- 禁止把固定主角在不同故事中扮演游客/观察者，误判为新角色并重复建卡。
- 禁止把红眼睛/蓝眼睛等本期知识身份直接覆盖到固定主角基础资产上；需要该状态时使用本期角色或明确的衍生状态。
- 禁止用长篇剧情对白取代 VO 的知识讲解；角色对白只在确实增强理解时少量使用。
