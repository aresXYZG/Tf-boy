# Toonflow 知识科普提示词优化复核

## 结论

网页回答的主诊断成立：`explainer_video` 目前把科普内容过度压成“趣味短剧五步法”，真正缺口在知识结构、证据边界和视觉证明功能，而不是镜头数量。Claude 补丁适合作为生产侧修补，但不应直接覆盖现有通用生产规则。

本次复核未改动业务提示词；本文件记录可直接实施的优化蓝图。

## 当前实施状态

本轮已按上述判断落地 5 个 explainer_video 文件：

- `data/skills/content_formats/explainer_video/production_execution_director_plan.md`
- `data/skills/content_formats/explainer_video/production_execution_storyboard_table.md`
- `data/skills/content_formats/explainer_video/script_execution_skeleton.md`
- `data/skills/content_formats/explainer_video/script_execution_adaptation.md`
- `data/skills/content_formats/explainer_video/script_execution_script.md`

另外，检查发现脚本 Agent 工具集中没有 `insert_script_to_sqlite`；已把科普剧本阶段的入库说明改为：只输出 `<scriptItem>`，由上层工作区流程解析并保存，避免继续引导模型调用不存在的工具。


生产阶段不是“同名文件自动覆盖/合并”。`src/agents/productionAgent/index.ts` 中明确读取：

```text
通用 production_execution_director_plan.md
  + "当前内容形态覆盖规则（优先遵守）"
  + content_formats/<contentFormat>/production_execution_director_plan.md
```

分镜表同理。也就是说，当前目录下每个形态只有一份同名 overlay；后加载内容是追加文本，不是按字段覆盖。`vertical_episode/新建 文本文档.txt` 是一个误拼接的重复文件，不在固定映射中，建议后续单独清理，但不要把它当成正式 patch 层。

剧本阶段则由 `src/agents/scriptAgent/index.ts` 依据 `contentFormat` 直接读取 `content_formats/<format>/script_execution_{phase}.md`，不是通用剧本文件加 overlay。因此知识结构改造必须同步 script skeleton、adaptation、script，不能只改 production 两个文件。

## 2. 评价网页回答：哪些正确

- 用知识结构类型取代固定 Hook/误区/拟人/脑洞/金句顺序：正确，应成为 explainer skeleton 的主路由。
- Claim Chain：正确，应至少包含现象/问题、主张、机制、证据来源、成立条件与边界。
- 类比登记“原理—类比—失效点”：正确，能防止把比喻当事实。
- 视觉转译从“默认拟人化”升级为物理过程、流程动作、时间变化、尺度对比、空间关系、历史重演、数据具象化等决策：正确。
- Visual Function（这个画面证明什么）：正确，应进入阶段 2 和阶段 3，并最终落到分镜表字段。
- “连续高密度后安排缓冲”优于“每 30 秒一个梗”：正确，应设为软规则。

## 3. 需要修正的地方

### 3.1 不要把所有科普都叫“故事/谜题”
当前 production overlay 的“每个故事/谜题独立闭环”和“现实游客视角 ↔ 谜题内部角色”过窄。科普应允许：实验演示、历史重演、数据解释、流程拆解、真实场景观察、微观机制可视化。固定主角与知识角色都应是可选项，无角色时以实物/图形/场景为主。

### 3.2 不要把证据责任推给导演规划
导演规划只能核对输入剧本/原文是否提供依据，不能替研究阶段补充事实。它应标注“依据类型”和“未提供/待核实”，而不是自行查证或编造。

### 3.3 不要宣称一致性完全由系统保证
当前代码会保存分镜关联资产 ID，但视频提示词生成链路 `src/routes/production/workbench/batchGeneratePrompt.ts` 主要把 `videoDesc` 与资产名称交给 `universalAi`；此处没有直接把 `referenceList` 传入模型。应保留“分镜表必须引用真实资产”的约束，并把系统一致性描述改为“资产绑定可复用，最终一致性仍依赖实际生成链路”。

### 3.4 不要在通用层硬塞科普规则
通用导演规划适合维持场次、台词统计、情绪、资产和 XML 契约；通用分镜表适合维持 Track ≤15 秒、行字段、音效、台词、资产 ID 和连续性。科普的 Claim Chain、证据、视觉功能、视觉转译应留在 explainer overlay 或 script 阶段。

### 3.5 先解决互相冲突的禁令
当前通用分镜表整体禁止“光影/色调”，而 `Fun_science_director/director_storyboard_table_narrative.md` 仍多次要求光影/色彩；当前提示词技法也仍有光影段。不要在 explainer overlay 中重新引入光影要求。应以当前通用生产禁令为准，把科普画面改写为主体、动作、空间、材质、粒子/流体/数量变化和时间变化；若未来允许光影，应统一改通用规则而不是形态层私自突破。

## 4. 推荐的四阶段改造分工

### A. event_extraction.md：只做材料结构化，不做时长
保留现在六字段、无秒数约束的方向。建议把“知识机制”拆成更可靠的字段契约：

- 核心问题
- 核心概念
- 现象/事实
- 原文给出的机制
- 证据/案例及依据类型
- 常见误区
- 认知变化
- 信息密度
- 观看情绪

但考虑当前解析结果依赖一行、固定字段，扩字段前要同步读取方和历史数据兼容策略。短期可以不改字段数量，而要求知识机制字段内部按“现象 → 机制 → 结论；证据缺失写未提供”组织。

### B. script_execution_skeleton.md：核心改造，改为“认知骨架”
这是最高优先级。新增：

1. 知识结构判定：机制解释 / 历史事件 / 数据现象 / 流程方法 / 谜题推理。
2. 核心问题、核心结论、最大误区。
3. 1~3 条 Claim Chain：主张、机制、证据、成立条件、边界。
4. 认知递进：观众原认知 → 新信息/证据 → 新认知 → 下一问。
5. 视觉转译决策：首选视觉方式、可拍视觉事件、该画面证明什么、是否拟人化。
6. 类比登记：成立部分和失效点。
7. 只有材料支持时才使用极端推演；没有证据不补事实。
8. 时长按知识完整性和项目配置推导，不能为了填时长灌水。

“Hook”保留，但只负责制造一个问题，不再要求常识粉碎、拟人化、脑洞和金句四件套全部出现。

### C. script_execution_adaptation.md：从语言降维改为认知/视觉转译
建议输出五张小表或等价短节：

- 术语与人话：术语、最小定义、必要程度。
- 主张与证据：每条 VO 主张对应原文事实/实验/数据/历史记录/案例/未提供。
- 类比登记：原理、类比、成立部分、失效点。
- 视觉事件表：主张、视觉方式、正在发生的动作、Visual Function。
- 节奏表：信息密度、VO 区间、视觉事件密度、缓冲点。

“拟人化”改为可选项；默认优先选择真实物理过程、流程、尺度、时间轴和空间关系。删减只允许删冗余，不得删掉支撑主结论的证据、条件和限制。

### D. script_execution_script.md：给每个镜头增加 Visual Function
现有 `VO + Visual + Motion` 保留，建议增加：

- `视觉功能 (Visual Function)`：此画面正在证明/解释/对比/提示什么。
- 每镜一个主要视觉事件，但不要求每句 VO 都强行切镜。
- VO 与画面可互补，但不能互相矛盾；画面不能只做“酷炫 B-roll”。
- 类比画面必须在脚本或备注中标注其为类比，不可让观众误以为真实机制。
- 数据/历史/医学内容没有输入证据时，VO 使用“材料未提供/待核实”或不写该结论，不自行编造。

## 5. 两个 production overlay 应如何改

### production_execution_director_plan.md
它不应该重新设计知识内容，而应该把 script skeleton/adaptation 已产出的认知契约落地到场次：

- 读取剧本和 assets 一次，保持通用工具边界。
- 将每个知识段的 `认知功能 / 证据落点 / 视觉事件 / Visual Function / 音画关系` 写进逐场注意事项。
- 依据知识结构选择场景组织方式，不默认“谜题内部世界”。
- 记录固定主角/本期知识角色是否存在；没有角色时明确“实物/图解/场景”。
- Track ≤15 秒仍是生成物理约束，但不能拆断一条因果链。
- 高密度段后给视觉缓冲软规则，不设每 30 秒固定梗。

### production_execution_storyboard_table.md
它应在通用表格字段不变的前提下增加科普执行要求：

- VO 仍是主要时间轴；`画面描述`必须包含一个可见视觉事件。
- 新增或复用 `视觉功能` 字段，明确画面证明什么；如果当前前端/解析只认固定列，优先把它写入“画面描述”或“备注”，不要贸然改结构。
- 机制段优先采用“现象/真实过程 → 机制可视化 → 证据/例子 → 结论回收”，而不是固定“主角反应 → 群体示意 → 日期牌”。
- 拟人化只在降低理解成本时使用，并锁定概念形象；无角色内容不强行造人。
- 数据用数量、尺度、时间变化、空间关系或简单图形动作表达；历史用事件重演；流程用连续动作；抽象关系用经过标注的生活类比。
- 连续 2~4 个高信息镜头后可插 1 个不新增知识的短缓冲；缓冲不强制、不为凑数。
- 画面描述不得添加输入未给出的数字、年份、实验结果或结论。
- 资产 ID 只引用真实资产；不要写“系统一定保证一致性”，改成“沿用真实资产绑定，生成一致性取决于后续参考链路”。

## 6. 四种内容形态的边界

| 形态 | 第一原则 | production overlay 应强调 | 不应强套 |
|---|---|---|---|
| vertical_episode | 先情绪，再信息 | 3-5 秒冲突、集内推进、卡点 | 科普式解释、Claim Chain |
| series_drama | 先关心人物，再追因果 | 人物选择、弧光、自然集间承接 | 付费点、知识闭环 |
| single_film | 先经历选择，再理解主题 | 单片闭环、三幕/等价节拍、视觉母题 | 分集卡点、知识字段 |
| explainer_video | 先制造认知缺口，再用证据和因果填上 | 认知结构、证据边界、视觉证明、VO/画面互补 | 剧情爽点、固定拟人、固定五步法 |

## 7. 实施优先级

P0：先改 explainer 的 `script_execution_skeleton.md`；否则生产侧只能对错误/空泛的脚本做镜头包装。

P1：改 `script_execution_adaptation.md` 和 `script_execution_script.md`，建立类比边界与 Visual Function。

P1：再改两个 explainer production overlay，让导演规划和分镜表消费新契约。

P2：重新审查 `Fun_science_director/director_storyboard_table_narrative.md`，去掉与当前通用规则冲突的光影/固定拟人化强制要求，或确认它只作为风格可选技法而非 explainer 必选规则。

P2：统一时长/语速/Track 口径。当前不同层存在 150 字/分钟、180~220 字/分钟、单镜 3~8 秒、3~10 秒、Track ≤15 秒等多套规则。推荐：项目配置优先；Track ≤15 秒为硬约束；单镜时长服从通用分镜表；科普 VO 语速只作为估算区间，不覆盖项目配置。

P3：再考虑代码层支持真正的结构化 overlay/patch。当前代码只是字符串追加，无法执行“只覆盖冲突字段”。在没有代码改造前，不要继续堆 patch 文件。

## 8. 验收标准

用至少五类样例回归：机制（天空为什么蓝）、历史（长城为何修）、数据（房价与生育率）、流程（芯片制造）、谜题（红眼睛居民）。每类检查：

- 是否选对知识结构，而不是都输出五步法。
- 核心问题、结论、误区、证据与边界是否齐全。
- 画面是否能证明 VO，而不是装饰性 B-roll。
- 类比是否标出失效点。
- 无材料依据时是否明确未提供/待核实。
- 是否仍满足 Track ≤15 秒、真实资产 ID、无新增剧情和 XML/工作区契约。

## 推荐决策

**应该按网页回答的方向做，但不要照抄它的完整重写稿。** 正确路线是：先把 explainer 的剧本三阶段改成认知管线，再让两个 production overlay 负责落地；通用层保持稳定。Claude 补丁保留其中“VO 与视觉事件绑定、关键结论前留白、连续高密度后的视觉缓冲”等生产规则，但将“固定 30 秒视觉梗”和“固定谜题/游客视角”降级为可选策略。
