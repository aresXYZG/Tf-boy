## 一、核心结论与准则明确（避免误判与过度优化）

**「55秒/集 + 分集收费」不是系统硬限制，而是在特定场景下的「超短剧商业逻辑」。** 随着系统扩展至连续剧与微电影形态，系统已全面支持三大内容形态的解耦与自由切换。

### 关键准则明确

1. **「15秒多镜头片段（Track）」设计完全正确且符合物理上限**：
   - **模型能力**：主流视频生成大模型（如 MiniMax、Seedance 2.0 等）单次视频生成的物理上限就是 **15秒**。
   - **镜头与片段解耦**：单个 15s 片段（Track）内部推荐承载 **1~3 个镜头**（单镜头 3~10s），打破过去 1 镜头 = 1 片段的死板绑定。15s 规格既是视频生成的最高效批次单元，也是多镜头连贯剪辑的最佳实践，**绝不可将其作为“冲突”随意缩减**。
2. **语速口径保持现状**：
   - 剧本侧（150字/分钟，约2.5字/秒）与制作侧（分镜字数评估）当前在实际运行中已形成默契，**暂不做任何修改**，避免破坏已稳定的短剧台词节奏与审核判定。
3. **内容形态解耦已落地**：
   - 通过 `contentFormat`（`vertical_episode` / `series_drama` / `single_film`）实现按形态动态激活/关闭付费卡点、投流爆点与分集逻辑。

## 二、三大内容形态（ContentFormat）规范

```ts
type ContentFormat = "vertical_episode" | "series_drama" | "single_film";
// vertical_episode —— 超短剧：竖屏分集 55s/集，激活付费点+投流爆点
// series_drama      —— 连续剧：横屏/竖屏 5~15 分钟/集，多幕叙事，去短剧卡点
// single_film       —— 短故事/微电影：整片单集闭环（3~120 分钟），无分集
```

### 约束集 Profile

| 维度 | 超短剧 (`vertical_episode`) | 连续剧 (`series_drama`) | 短故事/微电影 (`single_film`) |
|------|---------------------------|------------------------|-----------------------------|
| 叙事结构 | 分集叙事（默认 55s/集） | 多集多幕（5~15 分钟/集） | 整片单集闭环（单集完结） |
| 付费卡点 | ✅ 激活 10/30/50/70/90% | ❌ 关闭 | ❌ 关闭 |
| 投流爆点 | ✅ 激活前10集30s爆点 | ❌ 关闭 | ❌ 关闭 |
| 集末钩子 | ✅ 激活每集卡点悬念 | ❌ 幕间转折 | ❌ 闭环结局 |
| 生成片段 | 单片段 ≤15s（1~3镜头） | 单片段 ≤15s（1~3镜头） | 单片段 ≤15s（1~3镜头） |
| 单镜头时长 | 推荐 3~10s | 推荐 3~10s | 推荐 3~10s |

## 三、新建项目与 Agent 交互体验准则

1. **新建项目默认智能预选**：
   - 图片模型：优先自动匹配并预选 `image-2` / `gpt-image-2` / `flux` 等高质量模型；
   - 图片画质：默认预选 `2K`；
   - 视频模型与模式：自动预选可用视频模型，并默认选中 `singleImage (单图参考)` 模式；
   - 视频比例：默认预选 `16:9`。
2. **剧本参数后置推断机制**：
   - 新建项目时允许 `intro`（剧本简介）、`totalEpisodes`（总集数）等留空；
   - 剧本编剧 Agent 解析小说章节事件后，自动评估剧情体量并给出推荐大纲与集数，用户确认后自动反写回项目。

15s 片段与现有语速设计完全符合实际生产管线要求。通过将形态开关与智能预选全面落库，系统已在保持超短剧高效产出的同时，稳健支持了长剧与微电影制作。
